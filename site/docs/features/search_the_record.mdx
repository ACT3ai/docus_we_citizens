# Search The Record

One search box sits in the header of every page, and it does one job: you type a name and it takes you to that record. It reaches the politician rosters and all three law libraries, and it keeps no record of what you typed — not for a signed-in citizen, not for a visitor who never signed in.

## What it does

The box searches four stores at once. Both **politician rosters** are in it — the people who have held office and left a roll-call record, and the people worth electing who never have. So are all three law libraries: the **problem law** groups, the **good law** campaigns, and the movement's own **fix bills** that nobody in Congress has filed.

The index is built by reading through the same services the list pages render from. That is the whole reason it can be trusted: it cannot know something a page does not know, and it cannot miss something a page shows. **A hit is by construction a page that already exists and is already public.** It builds on the first search and rebuilds at most once a minute.

It runs **inside the app's own backend**, in memory. An external search cluster was considered and rejected: this product has to run on a citizen's own computer with no outside services, and the corpus is a few thousand records. A cluster would have been the heaviest component in the product, guarding the smallest data set in it.

Matching is built for someone typing a half-remembered name. It matches on **prefixes**, so results refresh from the second character, and carries **light fuzziness**, so a misspelled surname still lands. The title field weighs more than the detail text: someone typing a person's name wants the person, not a law whose summary mentions them.

* A result is one row: a kind label — Politician, Good law, Problem law, Fix bill — the title, and one muted line of detail. Choosing it opens the record; Enter opens the top hit.
* Hits are capped at twenty. This is navigation, not analysis; the exhaustive list is what the list pages are for.
* When nothing matches, the empty state says what was searched — "nothing matched across N politicians and laws" — so an honest zero never reads as a broken box.
* When the header is crowded, the box collapses to a magnifier button that opens the same search in a popover. It yields header space to the page's own title and actions, never the reverse.

## The goal it serves

The whole argument of this site is that you do not have to take anyone's word for anything: the record on a named politician or a named law is public, sourced, and checkable by you. That collapses at the last inch if someone who arrives to check one person cannot find them in ten seconds. Evidence nobody can reach is not evidence. Search is the difference between [a library of the record](/docs/laws/the_four_libraries) and a library with the lights off.

It has to work for someone who has committed to nothing, so search is never gated. A visitor who has not signed in, a signed-in citizen, and someone running the app on their own laptop get the same hits. The first thing a skeptical person does is look up their own representative and check our account against what they already know. A sign-in wall there asks for trust before offering any.

The rest is a movement commitment rather than a feature. We ask people to look up who represents them. **A movement that kept a log of who looked up whom would be building the instrument it exists to argue against** — quiet records of ordinary behavior, held by someone else, available later. So the box writes nothing: no query log, no per-citizen history, no saved-search list stored against anybody. It is the same commitment that puts the whole product on [your own machine by default](/docs/get_started/run_it_on_your_computer), and the reason this project can [name the American version of a social credit system](/docs/no_social_credit/overview) without collecting the same exhaust.

## What keeps it honest

* **Results are never filtered by who is asking.** There is no personalization here and no place to put one, so nobody is quietly shown a different version of the record.
* **It cannot surface what a list page could not.** A pending proposal, an unapproved record, or a private profile field is not in the index, because it is not on a page.
* **If search ever grows a write, that write is a different surface.** Saved searches or a recent-searches list would be a contribution and would take the movement's full gating rules. The box stays open regardless.
* **A store that fails to read is named, not hidden.** If one of the four cannot be read this minute, that is logged and the store is absent from the index for the minute. Search answers from the other three rather than pretending the missing one came back empty.
* **It does not judge anything.** Search computes no award and decides nothing about a person. It gets you to the page; the page carries the arithmetic.
