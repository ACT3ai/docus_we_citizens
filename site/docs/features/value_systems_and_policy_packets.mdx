# Value Systems And Policy Packets

Everyone carries rules about what matters more than what. Liberty over safety, until the harm is real and proven. Equal treatment over efficiency. Most people never write those rules down, so nobody can apply them but the person holding them, one situation at a time. A value system is those rules written down in a form software can act on. A policy packet is that same file handed to another citizen who wants to reason the way you do.

## What it does

A **value system** is a named, versioned record with three blocks in it, and the three map onto how a person actually reasons.

* **Ordered rules** are the this-versus-that logic. Each one reads *when* a named conflict arises, *prefer* this side, *unless* a named exception holds. Each carries a weight from 0 to 1 for how strongly you hold it, and a rationale in your own words. They are read top down, and the first rule that matches without its exception firing is the one that decides.
* **Standing principles** are unconditional. They are not comparisons, they are statements a recommendation is not allowed to violate.
* **Ranked priorities** are a plain list, most important first. They break a conflict no explicit rule covers.

Everything except the name defaults, so a value system holding one rule is valid and usable from the moment you save it. You can keep several — one for civic questions, one for economics — and choose which one judges what.

The **Apply** surface is what the structure is for. You type in a situation and get back a recommendation reasoned from your own rules, with the firing chain visible: which rules matched, which exceptions applied, which priority broke the tie when nothing else did. The answer never arrives on its own. It arrives with the derivation that produced it, so you can say the machine read your rules wrong, or that the rule itself was wrong.

None of that is gated. Authoring, editing, importing and applying are a citizen's own reasoning sitting in a file on their own disk. In Individual Mode there is no account and no server involved, and this is one of the four pillars a person can complete end to end without ever signing in.

Publishing is the one act that crosses out of your own tree. A finished value system becomes a **policy packet** — a self-contained file another citizen's copy of the software can read — stamped with who published it and when. That stamp is why publishing, and only publishing, requires a verified identity; the local default user is refused. On the other side, the packet caches under your name in the importer's tree, so they can weight it by how far they trust you. An imported packet is read-only reference: it can be read, applied, or cloned into an editable copy of their own, and re-importing refreshes only that one cached file.

## The goal it serves

This is the movement's answer to being told what to think. The ordinary arrangement is that somebody in Washington, or a media outlet, or an interest group with a budget, decides what a reasonable position is and citizens are handed the conclusion. This inverts it. You state the rules; the software works out what follows from them. Nothing here supplies a position you did not put in.

It also answers a scale problem that is doing real damage. There is far more legislation, spending and procedure than any working person can read, and that gap is what makes capture cheap — most of it goes by unexamined. Rules written down once can be applied across more material than you could review by hand, the same way every time, which is more than most institutions manage. That is the same reason a [decision](/docs/decisions/overview) is measured against a fixed yardstick rather than against a mood.

Then it makes ethics shareable the way software is. Somebody who has thought carefully about a domain publishes their reasoning as a packet, and a citizen who trusts that person starts from considered rules instead of a blank page — then edits them, because the clone is theirs. That is a movement building shared standards from the bottom rather than a platform issuing them, and it is why the [trust score](/docs/trust_scores/overview) on an author matters: you decide whose reasoning you are willing to borrow.

## What keeps it honest

The feature applies your rules. It does not supply them. An empty value system produces nothing, and there is no house position hidden underneath the one you wrote. If a recommendation is wrong, the fired rules are on the screen and the fault is locatable — in the rule, in the weight, or in the match.

Three other limits are deliberate:

* **A value system judges a situation, never a person's record.** It is not an award, and nothing it produces reaches the Monkey, Llama or Flamingo Awards. Those are computed from evidence about a politician; this is your own reasoning about a question.
* **The author's name stays on an imported packet.** The original is never silently changed, editing means cloning, and a re-import refreshes only the cached copy.
* **The build state is stated plainly.** The Apply step today runs a deterministic rule matcher inside the app rather than a language model, and reports itself as such; attaching an applied result into a decision's record is specified but not yet wired.
