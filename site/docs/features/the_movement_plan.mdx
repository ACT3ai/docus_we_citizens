# The Movement Plan

A movement that asks you to judge officials against a written record owes you one of its own. The Plan is that record: what We The Citizens says it is going to do, published as a numbered document you read from the top instead of a dashboard you skim. Every item carries a button that asks you one question about it — whether it belongs on the plan at all.

## What it does

The plan lives as one committed document in the movement's public data repository. It is a written file, not a table of records the page reports on: groups first, then the numbered items a citizen refers to out loud, then sub-sections inside an item such as *How we know it's done*. The page renders that document essentially as it was typed, at a comfortable reading width, with the item headings the largest text on the page and the group headings deliberately quiet above them.

Every group heading and every item heading carries a **frozen key**, written visibly in the source next to the title, in the form `{#open_source_voting}`. A heading with no key is reported as a broken file — the software does not fall back to deriving one from the title. That refusal is the point. If the key came from the title, a copy-edit would quietly re-file every answer already cast onto a different item, and nobody would see it happen. Titles can be rewritten freely; a key never is.

The **numbers are computed on render**, counted straight through the whole document, and never written into the file. Insert an item in the middle and everything below it renumbers on the next load. No answer moves, because no answer was ever filed under a number — it is filed under the frozen key.

A **directive** puts a working control inside the document. Where the author writes the vote directive, the renderer replaces it with a real **Vote on this** button for that item, so the ask lands where the author placed it rather than being pushed to a margin. An item whose author forgot the directive gets the button appended anyway. The ballot behind it restates the item in full and asks one generated question — is this worth fixing — with a Yes and a No, and it says what each answer means before you pick one.

Deliberately absent: status chips, owner chips, priority numbers, and progress rollups. Those were the storage format leaking onto the page, and each one sat between the reader and the sentence it was decorating.

Behind the document sits a versioning layer that a citizen never has to look at. A year either **tracks** the living plan, **derives** from it with its changes recorded, or is **locked in** as a frozen snapshot. Once a year is locked, later edits to the living plan reach future years and not that one — so a past year can be put side by side with what the movement now says it intends. Reading is never gated. Only admins edit it.

## The goal it serves

A citizen who has just decided to help needs to know what the movement is actually going to do, in enough detail to disagree with. That is a different need from being reassured. A plan you can only skim as a chip-covered table is a dashboard; a plan you read end to end, and answer item by item, is a commitment somebody can be held to later.

The whole argument this site makes is that officials should be measurable against their own record rather than their own promises. A movement that made that argument and then published nothing checkable about itself would be asking for a trust it had not earned. The Plan is that standard turned around and pointed inward: written down, committed in public, and dated. Freezing a year is the part that costs something — it means the movement can be shown what it said in 2026 and asked what happened to it. That is the same test the [Charter](/docs/the_movement/charter) sets for everything else the movement does.

The vote button is there because a plan nobody can answer is a newsletter. It is the shortest path from reading to doing: the first thing you can do about the movement's direction, before you have vetted anybody or logged anything, is say whether an item belongs on the list. See [The Movement](/docs/the_movement/overview) for what joining involves, [How It Works](/docs/how_it_works/overview) for where this sits in the wider loop, and [Decisions](/docs/decisions/overview) for the larger machinery this ballot is the simplest case of.

## What keeps it honest

* **A broken file is reported, not hidden.** If a heading is missing its key or the file will not parse, the page names the exact file and the heading that failed, above everything it could still render. A plan that half-renders with its problem named is honest. A blank page is not.
* **A directive that is not recognised renders visibly**, in place, saying what it said. It is never silently dropped, because a call to action that quietly vanished from a published document is exactly the kind of gap nobody would notice.
* **No progress bar where there is no progress to count.** A document plan carries no per-item status, so the rollup is hidden rather than showing "0 done" — an absent bar is the truth, and a zeroed one is a claim.
* **The vote is not a finding.** It records what citizens said about whether an item belongs on the plan. It is not a vote on how to fix the thing, not a vote on the wording, and it decides nothing on its own.
* **Answers outlive the items.** Remove an item from the plan and the answers cast against it are kept and reported as orphaned, rather than deleted along with the inconvenient question.
* **The asymmetry is stated.** Only admins write the plan. Every citizen reads it, including a visitor who is not signed in and a person running the software on their own machine.
